## 1. What it is

An evidence-annotated DNS blocklist for LG webOS TV telemetry (what the TV reports about what you watch/do), ads, and phone-home traffic, in two tiers:

| Tier | Blocks | Cost |
|---|---|---|
| **SAFE** | Proven telemetry, ads, ACR ("what are you watching" reporting) | Netflix/Prime/HBO/YouTube, Content Store, app updates keep working (verified live on an LG G1) |
| **STRICT** | Everything in SAFE **plus** firmware OTA, ThinQ cloud sync, LG Channels | Those services stop working *by design*; LG Content Store may degrade; LG account login may fail |
| **ZONES** (STRICT-only) | 9 apex anchors for whole-zone blocking (`\|\|zone^` in adblock format) | Only whole-family coverage; in exact-name formats they block the apex only |

STRICT is compiled as `safe.txt + strict.txt` (strict is the *delta*). `src/` is the source of truth; `lists/` are CI-generated (8 outputs: `-domains`, `-adblock`, `-hosts`, `-wildcard` per tier + SHA256SUMS).

## 2. Methodology (docs/methodology.md)

- **Two-week root-level audit of a real LG G1** (German network, webOS 6): ~44,800-packet capture, 267,000-query DNS log, per-service investigation (root, service kills, iptables, hosts hooks). Entries were *authored from audit data, not scraped from other lists*.
- **Two independent observation layers:** (1) DNS logging resolver with per-client attribution; (2) packet capture (dns.qry.name, TLS SNI, IP-literal traffic). The packet layer catches traffic the DNS layer never sees.
- **Evidence grading per entry:** boot bursts and fixed-cadence heartbeats beat one-off hits (the ACR beacon `cdpbeacon.lgtvcommon.com` queried ~every 6 min). "Weak" = observed but function unproven → STRICT only.
- **Live blocking verification:** a domain enters SAFE only after app smoke tests (Netflix, Prime, HBO, YouTube, store, app install/update all pass).
- **Reproducibility tooling:** `scripts/verify.py` (DoH liveness check — deliberately DoH because the maintainer's own blocker sinkholes the names and `dig` would report the blocklist back), `scripts/check_blocking.py`, `scripts/localize.py`, CI test suites (45/16/18/44/89 tests green as of 2026-09-16), SHA256SUMS, build guards (`FORBIDDEN_APEX_ENTRIES` hard-errors if bare `lgtvsdp.com` ever returns to any `src/` file).
- **Known limitations (self-declared):** one model (G1), one region (Germany), no exact firmware build recorded in the original audit; exact-name semantics; region endpoints enumerated only where observed.

## 3. The LG DNS bypass (how the TV escapes your resolver)

This is the repo's most important operational finding, documented in `docs/methodology.md` ("the gotcha that breaks naive setups"), README caveat 1, and issue #5:

1. **webOS runs its own stub resolver on `127.0.0.1:53`** (issue #5: `/etc/resolv.conf` shows `nameserver 127.0.0.1`, "Generated by Connection Manager"; `netstat` shows `127.0.0.1:53` LISTEN). Daemons query this stub directly.
2. **The stub resolver does not read `/etc/hosts`.** Observed: `nslookup <host> 127.0.0.1` returns a real upstream CNAME while `getent hosts <host>` on the same TV returns the local null-route — the hosts file and the stub disagree about the same name. A hosts file alone is therefore insufficient.
3. **Daemons hardcode public resolvers** (`8.8.8.8` / `1.1.1.1`) as fallback and can use encrypted DNS (DoT :853, DoH).
4. **Consequence:** "point the TV at your resolver, watch the log, and it looks suspiciously clean" is a false negative — queries via the stub/hardcoded/encrypted paths never appear in your log.
5. **Mitigations (repo's fix stack):**
   - Redirect TV outbound port 53 to your resolver at the firewall; block outbound 853 (DoT); block known DoH endpoints.
   - Rooted TV: `examples/webos-hooks/02-block-dns-egress.sh` (webosbrew `init.d` boot hook) does the DNAT 53→resolver + 853 drop on-device.
   - `04-sync-clock.sh`: sets the clock from an HTTP `Date:` header at boot, because blocking the LG time channel can leave a cold-booted TV with a 2021-01-01 clock, which breaks strict-TLS downloads (Homebrew Channel error `(0)`).
   - IPv6 is another bypass path — **issue #4 (open)**: the egress hook is IPv4-only.
6. **Time sync is not NTP at all:** furkan's own test (issue #6, 2026-09-14, on their G1 with the hook active): no ntpd/ntpdate/ntp.conf; `systemTimeSource=sdp` — the clock is taken through **LG's SDP session handshake**, i.e. the `*.lgtvsdp.com` / `*.nextlgsdp.com` families. Their G1 survives its blocks because it has fallback time sources (broadcast/MCU); other models (e.g. the G5 webOS 26 in issue #6) do not.

## 4. The eic / aic / kic datacentre-cluster story

Discovered 2026-09-12 by contributor `sink-await` (PR #7, "Add 53 live datacentre-cluster endpoints; the ACR beacon moved and is currently unblocked"):

- LG fronts many services from **three regional datacentre clusters, independent of country codes**: `eic` = Europe, `aic` = Americas, `kic` = Korea. Separators vary: `eic.lgtviot.com` (dot) but `eic-ngfts.lge.com` (dash).
- **The G1 audit ran in Germany, so it only ever saw `eic.*`.** Every `eic.*` entry had live `aic.*`/`kic.*` twins that were absent from the list — non-European TVs were substantially uncovered even for hosts the audit had found.
- **The ACR beacon had moved:** bare `cdpbeacon.lgtvcommon.com` (also `ads.`, `homeprv.`, `recommend.`, `service.`) is now NXDOMAIN; the live names are `eic./aic./kic.<stem>.lgtvcommon.com`. In exact-name formats (`-domains.txt`, `-hosts.txt`) the beacon was **simply unblocked** until 2026-09-12. The 5 moved services' successors were filed as `weak` in `src/strict.txt` (DNS-verified only).
- **Naming is confirmed, not guessed** — by LG's own CNAME targets:
  - `de.emp.lgsmartplatform.com` → `eic-emp-lgsmartplatform-com.lgemp-prd.net` (AWS eu-west-1)
  - `us.emp.lgsmartplatform.com` → `aic-emp-lgsmartplatform-com.lgemp-prd.net` (AWS us-west-2)
- **Enumeration method:** take each audited stem, probe all 6 cluster/separator forms over DoH (Google + Cloudflare cross-check; DoH used deliberately — see §2.6). 2026-09-12: all 53 returned NOERROR with an A record. 18 candidate three-letter prefixes were probed; **exactly `eic`, `aic`, `kic` exist** (no wildcard record making invented names look alive). Control: `zz.`, `qq.`, `xj.` all NXDOMAIN.
- **Certificate evidence** (PR #14, `docs/certificates.md`): DoH-resolve each cluster name, TLS handshake with SNI, verify the presented certificate is valid for the exact name (SAN match, certs issued to LG — Amazon/DigiCert/Let's Encrypt per family): **62 of 65 pass**. The 3 failures: `aic.`, `eic.`, `kic.lgthinq.com` resolve into **Azure** ranges (unlike every other family, which is on AWS) and never complete a handshake on 443. Recorded absence: `kic.lgshopsvc.lgappstv.com` does **not** exist while `aic.`/`eic.` do (the only asymmetric stem in the set).
- **Evidence grade (repo's own wording):** cluster twins carry "**DNS existence, not traffic observation**". A regional querylog/capture is the only thing that promotes a twin from `weak` (STRICT) to SAFE.
- **Tiering policy:** tier follows the *cluster sibling*, never the zone apex; but per current `src/strict.txt` header, twins whose sole evidence is DNS on a SAFE/weak lineage are kept in STRICT tagged `weak` — "never risk SAFE on a guess". Net current state: all 53 cluster entries sit in `strict.txt`; SAFE retains only the five `eic.*` hosts with actual traffic evidence.

## 7. Breakage evidence (domains that broke TV functionality when blocked)

### 7.1 `lgtvsdp.com` — the TV's time channel (the repo's own catch, 2026-09-16)

- **Symptom:** clock stuck after cold boot → **LG Content Store / app TLS fails** (certificates appear expired/invalid).
- **Mechanism:** adblock-format entry `||lgtvsdp.com^` covers *every* `<cc>.lgtvsdp.com`, including the region hosts LG uses for its SDP time handshake (`systemTimeSource=sdp`). Exact-name formats didn't have this problem (apex is SOA-only).
- **Evidence chain:** issue **#6** ("NTP Time Sync not working", LG G5 webOS 26, STRICT + DNS-egress hook; reverting the suspected entry fixed it; maintainer's own G1 test confirmed the SDP time mechanism, 2026-09-14) + a field report from **Austria (`at.lgtvsdp.com`)** + external **hagezi/dns-blocklists#11438** (blocking the nextlgsdp family broke time sync on some models).
- **Fix (commit `3ea0f34`):** removed `lgtvsdp.com` + `us.lgtvsdp.com` from `src/safe.txt`; un-generalised the `^[a-z][a-z]\.nextlgsdp\.com$` regex (which had spread the same mistake to all regions); build guards `FORBIDDEN_APEX_ENTRIES` + `FORBIDDEN_REGION_FAMILIES` now hard-error if they return. Count: safe 21→19, strict 116→114.
- **Residual risk:** `de.nextlgsdp.com` (SAFE) is part of the same SDP time family — the repo's FAQ keeps an explicit "SDP/store comms" carve-out (allowlist `de.lgtvsdp.com`, `de.ibs.nextlgsdp.com`); their G1 survives blocks via broadcast/MCU time fallback, other models don't.

### 7.2 Breakage by design (STRICT tier, documented in README)

Blocking these in STRICT is *intended feature-kill*: firmware OTA (`snu/su*/lge.com`, `ngfts/gfts` + cluster `*-ngfts/*-gfts`), ThinQ app/voice cloud sync (`lgthinq.com` family), LG Channels (`lgechannel.com` — now dead/NXDOMAIN anyway). Content Store "may degrade"; LG account login "may fail". Cross-check: Perflyst independently documented `ngfts.lge.com` → "blocks thumbnails from loading in the LG Content Store" (commented out there).

### 7.3 Time-sync side effects of the fix stack itself

- Issue #6: hook + blocks broke NTP/SDP time on G5 (see 7.1).
- README: blocking LG's time-sync can leave a cold-booted TV stuck at **2021-01-01**, breaking strict-TLS downloads (Homebrew Channel error `(0)`) → `04-sync-clock.sh` hook as belt-and-braces.
- Issue #4 (open): egress hook is IPv4-only → IPv6 is a live bypass (also a "blocking broken" vector).

### 7.4 Service-moved breakage (silent unblocking, caught 2026-09-12)

`cdpbeacon/ads/homeprv/recommend/service .lgtvcommon.com` went NXDOMAIN while moving to `eic./aic./kic.` names — exact-name list users were **silently unblocking the ACR beacon** for an unknown period. Fixed by adding the 53 cluster names; the old names kept for audit. This is the repo's key argument for `verify.py` liveness checks.

### 7.5 No documented streaming-app breakage

README FAQ: "Will this break Netflix / Prime / HBO / YouTube? No — verified on an LG G1" (SAFE and STRICT). Perflyst's LG-specific breakage (time/channel/store — not streaming playback) is in `perflyst-lg.md`.
