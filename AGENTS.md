# AGENTS.md — Deploying TVGuard on a new machine / network

You are an agent with terminal access on a machine that will become (or has
just become) the TVGuard box: the TV's gateway + DNS + privacy firewall.
This repository is the complete, proven system. Your job: figure out the
machine/network facts yourself, adapt the ONE config file that is
machine-specific (`.env`), verify everything with the built-in tests, and
then hand the user a short, exact list of router/TV actions. The user does NO
server work — only physical actions on the router and the TV remotes.

Do not redesign anything. The architecture is fixed:

```
TV(s)  ->  THIS BOX (gateway + Pi-hole DNS + TVGuard nftables + privacy policy)
          ->  upstream router (stays router + DHCP)  ->  Internet
```

## 0. Read first (10 minutes, in this order)

1. `README.md` — the layout and the script catalogue.
2. `docs/ROUTER_NEXT_STEPS_V2.md` — the physical steps the user performs.
3. `docs/ROLLBACK.md` — how every step is undone (one command).
4. `docs/FINAL_BLOCKING_PLAN.md` — what the privacy tiers block/keep.

Key facts you must keep in mind:

- **The policy configs in `config/` are the source of truth and are
  network-independent.** The vendor policies (Samsung manufacturer-lockdown,
  the LG tiers) are already built, tested and documented. You do NOT rebuild
  them — you redeploy them. Resolved IPs are re-resolved automatically on
  every apply (runtime data, git-ignored).
- **The only machine-specific state** is `.env` (git-ignored; generated by
  bootstrap from `.env.example` + discovered host facts).
- Privacy policy starts **OFF** on any fresh box (state lives in
  `/var/lib/tvguard/privacy-state`, which won't exist yet). You enable it
  explicitly, only after the TV is pointed at this box.

## 1. Machine phase — do this yourself

### 1.1 Bootstrap

```bash
sudo ./bootstrap.sh
```

It is idempotent and safe to re-run. It: installs packages, checks port
conflicts (53, 3001, 3443), generates `.env` (record the password it prints),
deploys the pinned Pi-hole via `compose.yaml`, runs the Pi-hole self-test and
provisions the per-device groups, and installs (but does NOT enable) the
`tvguard.service` unit.

If it reports port conflicts, STOP and report them — something else on this
box owns DNS or the Pi-hole ports. Do not displace it.

### 1.2 Verify the base layer

```bash
scripts/health-check.sh                     # all host checks
sudo scripts/tvguard-selftest.sh             # mock-TV netns proof (self-cleaning)
docker ps                                    # pihole: healthy
```

### 1.3 Discover the network — do NOT guess

Answer every question below with live evidence, and write the answers into
`.env`:

```bash
ip -4 addr                                   # which interface + IP is this box
ip route                                     # what is the upstream router
ip -6 route | grep -v fe80                   # IPv6: MUST be link-local only (see safety rules)
scripts/discover-lan.sh                      # arp-scan + nmap + SSDP of the LAN
python3 scripts/ssdp-discover.py             # UPnP devices (TVs announce here)
```

Then identify the TVs and the upstream router:

- TVs are the media players on this LAN: match the discovered MACs/models
  against what the user tells you (which device is the TV, which is the hub).
- Confirm the upstream router is the DHCP server and that this box is NOT
  running a DHCP server (`scripts/health-check.sh` checks).
- For any device you cannot identify, capture it before classifying:
  `sudo scripts/capture-device.sh <IP> 120` (headers only).

### 1.4 Set the one config file

`.env` (all values, no secrets):

```ini
MODE=onearm-poc              # (or dualnic-gateway + WAN_INTERFACE= on a true dedicated box)
LAN_INTERFACE=<this box's LAN NIC>
LAN_SUBNET=<observed subnet>
GATEWAY_IP=<this box's LAN IP — the IP the TVs will use>
PIHOLE_IP=<same as GATEWAY_IP>
UPSTREAM_ROUTER=<the router's LAN IP>
WAN_INTERFACE=               # dualnic-gateway only
TVS="<TV IPs space-separated>"
SAMSUNG_TVS="<samsung TV IPs>"
GOOGLE_TVS="<google TV IPs>"
LG_TVS=""                    # LG webOS TVs, if any
STATE_DIR=/var/lib/tvguard
```

Rules:

- Only IPs that actually exist on THIS LAN. No placeholders.
- `TVS` must list exactly the TVs the TVGuard policy should cover, and each
  vendor list (`SAMSUNG_TVS`, `LG_TVS`, ...) must stay disjoint.
- Vendor scope is derived from these lists at build time (the policy YAMLs
  carry no `applies_to`) — a TV IP in the wrong vendor list means the policy
  applies to the wrong device. Fix the list, never the policy.

### 1.5 Enable TVGuard in monitor mode

```bash
sudo scripts/tvguard-enable-monitor.sh
sudo scripts/tvguard-status.sh
```

Monitor mode = logging only, no blocking. The privacy policy is still OFF.

## 2. Router phase — this is what you tell the USER

Copy this almost verbatim to the user. Adjust only the IPs/names.
No command line — the user is at the router and the TV remote.

> **Do these on the router:**
>
> 1. **Reserve the TVGuard box's IP.** In the router's device/IP list, reserve
>    (static lease for) the MAC of this box at `<GATEWAY_IP>`. Nothing else
>    changes on the router — it stays the router and the DHCP server.
> 2. **Do not** enable DHCP on this box. **Do not** add any port forwarding,
>    VLAN or routing change. The router is the only router.
>
> **Then, on each TV (TV settings → network → IP assignment):**
>
> - Set **Manual IP** (static):
>   - IP address: the TV's own address (keep its current one)
>   - Gateway / Router: `<GATEWAY_IP>` — the TVGuard box
>   - DNS: `<GATEWAY_IP>` — the TVGuard box
>   - Subnet: as per the network
> - If the TV is already pointed at this box's IP, tell the user there is
>   **nothing to do on the TV** — it picks this box up as soon as the IP
>   reservation is in place (a TV power-cycle makes it certain).
>
> Leave everything else on the TV exactly as configured (accounts, apps,
> remote pairing).

After the user confirms, verify yourself (do not ask them):

```bash
sudo conntrack -L | grep <samsung TV IP> | head   # TV traffic flowing through this box
python3 scripts/show-dns-activity.py <samsung TV IP>  # Pi-hole seeing the TV's queries
```

## 3. Privacy phase — re-enable exactly what was running

Only after the TV demonstrably routes through this box:

```bash
# 1. Prove the mechanism end-to-end (throwaway mock, self-cleaning)
sudo scripts/privacy-policy-selftest.sh all        # expect: ALL PASS, 0 failed

# 2. Apply the Samsung policy that was proven live
sudo scripts/privacy-policy-apply.sh samsung manufacturer-lockdown

# 3. Verify server-side
sudo scripts/privacy-live-check.sh                 # expect: N passed, 0 failed
sudo scripts/privacy-watch.sh 30                   # safety watch (start before user tests)
```

LG (only if an LG webOS TV was discovered in §1.3): add its IP to `LG_TVS`
(and `TVS`) in `.env`, re-run the selftest, then
`sudo scripts/privacy-policy-apply.sh lg manufacturer-lockdown`.
Samsung and LG are independent instances — one failing never affects the
other, and each rolls back with `sudo scripts/privacy-policy-disable.sh <vendor>`.

Then hand the user the physical checklist and STOP:

- Samsung: `docs/TV_MANUAL_TEST_CHECKLIST.md` (+ `docs/VOICE_BLOCK_VERIFICATION.md`
  for the voice-proof protocol — cloud voice MUST fail, everything else works).
- LG: `docs/LG_MANUAL_TEST_CHECKLIST.md`.

Tell the user the one-command rollback, in plain words:
`sudo scripts/privacy-policy-disable.sh` (or `... <vendor>`) removes only the
privacy layer — TVGuard monitoring, Pi-hole, NAT and every other service stay
up.

## 4. Safety rules — non-negotiable on any machine

- Never flush nftables or conntrack globally. All changes go through the
  TVGuard render → `nft -c` → replace mechanism.
- Never enable DHCP on this box. The upstream router stays DHCP server.
- Never create broad wildcards (whole manufacturer domains, whole CDNs, whole
  ASNs) or blanket TCP/443 / UDP/443 rules. Quota: exact domains, plus the
  narrow zone-suffix regexes already in the policy configs (which the
  keep-list overrides at IP level — KEEP WINS).
- Never attach a privacy group to a device that is not in that vendor's TV
  list in `.env`. Other household clients must remain byte-for-byte
  unaffected.
- Never capture application payloads. Captures are headers-only
  (snaplen ≤ 192, local, 0600, git-ignored).
- Never commit: `.env`, `etc-pihole/`, `captures/`, `data/privacy-policy/`,
  `data/manufacturer-unknown/`, `data/offline-reconnect/`, pcaps, raw DNS
  history.
- If anything fails mid-enable: stop, run `sudo scripts/tvguard-status.sh` +
  `scripts/health-check.sh`, report the failure, and only then roll back the
  privacy layer (`privacy-policy-disable.sh`). A broken TV beats a proud
  agent.
- IPv6: a proven deployment is link-local-only (no RA, no v6 default route),
  which is why IPv6 egress is not a bypass there. If THIS network has a v6
  default route, do NOT proceed to privacy — report it first (an uncontrolled
  v6 path would silently defeat the policy).

## 5. Definition of done

- `scripts/health-check.sh` → ALL CHECKS PASSED
- `sudo scripts/tvguard-status.sh` → monitor mode, correct TV list, NAT intact
- `sudo scripts/privacy-policy-selftest.sh all` → ALL PASS
- `sudo scripts/privacy-live-check.sh` → 0 failed
- Samsung policy active exactly as on the proven box (state line
  `PRIVACY-samsung=manufacturer-lockdown`), or LG once its IP is confirmed
- User has the physical checklist + rollback sentence in hand
- `git status` clean (nothing machine-specific staged)
